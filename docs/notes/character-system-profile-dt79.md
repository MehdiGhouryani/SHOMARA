# طراحی سیستم شخصیت برای بخش پروفایل — DT-79 (2026-11-20)

> درخواست مالک: «بهتره بپردازیم به طراحی کاراکترها برای بخش پروفایل».
> این سندِ طراحی (brief) است، نه پیاده‌سازی: انتخاب‌های باز صریح ثبت شده‌اند و اجرا بعد از تأیید
> مالک انجام می‌شود.

## ۰. قیود حاکم (چرا این طرح این شکل است)

1. **ADR-0051 (۲۰۲۶-۱۱-۱۹):** هیچ preset آواتار انتخابی، هیچ `avatarId` ذخیره‌شده و هیچ گرید
   «آواتار من» وجود ندارد. کودک یک شخصیت ثابت دارد. پس شخصیت‌ها در شمارا **راهنمای داستانی**
   هستند (تصویرسازی راهنما)، نه آواتار قابل انتخاب — این طرح هیچ ناحیهٔ انتخاب شخصیت نمی‌سازد.
2. **ADR-0035:** cast رسمی شمارا = **Main، Number، Dana، Fandogh، Roka** (۵ نفر).
3. **قواعد قرارداد handoff** (`design/handoff-home-ui-v3/01_DESIGN/CHARACTER_PLACEMENT_FA.md`):
   حداکثر ۰–۲ شخصیت در هر viewport (بیشترِ اوقات یک cameo)؛ nodeهای مسیر فقط آیکون topic می‌گیرند؛
   اندازهٔ cameo برابر `ShomaraCharacterSlot.Inline` (۷۲dp)؛ pose جدید ساخته نمی‌شود؛
   `ContentScale.Fit` حفظ می‌شود.
4. **ماتریس الهام (`docs/DESIGN_RULES.md`):** الگوی «cast شخصیت با نقش‌های متمایز» از Duolingo
   (اتصال عاطفی که طولانی‌تر از مکانیک می‌ماند) به‌عنوان **اصل** پذیرفته شده؛ خود شخصیت‌های
   Duolingo (جغد Duo، Lily، …) IP و ممنوع‌اند. هیچ شبیه‌سازی بصری از آن‌ها انجام نمی‌شود.
5. **قاعدهٔ درست‌نمایی:** فقط poseهایی که واقعاً در build shipped شده‌اند رندر می‌شوند؛ برای بقیه،
   placeholder صادقانهٔ missing-art (`ShomaraCharacterImage`) می‌آید — pose جعلی ساخته نمی‌شود.

## ۲. طرح پیشنهادی سیستم شخصیت (سه لایه)

### لایهٔ ۱ — «همراه پروفایل» با موجودی امروز (بدون artwork جدید)

- **کارت هویت (حالت Ready):** Main pose 01 (front) در slot ۷۲dp، decorative — **دست‌نخورده می‌ماند**.
  دلیل: ثبات هویتِ کارت (کودک هر بار همان همراه را ببیند) و مطابقت با ADR-0051 (یک شخصیت ثابت).
- **حالت Empty (پروفایل کامل نشده):** امروز فقط یک `FeedbackBanner` متنی است («پروفایل هنوز کامل
  نشده؛ از مسیر ادامه بده»). طرح: **cameo جمع‌وجور Fandogh (فایل موجود!) کنار همان پیام** — شخصیتِ
  «راهنمای تمرین/ادامه»، یعنی همان کسی که در empty state تب تمرین هم نقشش است؛ نتیجه: پیام یکدستِ
  «وقتی جایی خالی/منتظر ماندی، سنجاب راه را نشان می‌دهد».
- **حالت Error/Offline:** بدون شخصیت — خطا جایی برای دکور نیست (قاعدهٔ handoff: کاراکتر را برای
  پوشاندن خطا نشان نده).

### لایهٔ ۲ — «راهنمای مفهومی» (کارکرد محتوایی، بعد از لایهٔ ۱)

Number در لحظه‌های عدد/شمارش (پروفایل اگر روزی «پیشرفت به تفکیک موضوع» بگیرد، پیش‌پردهٔ هر
موضوع می‌تواند cameo Number pose 17 بگیرد). این لایه به O5/پروجکشن داده وابسته است و عجله ندارد.

### لایهٔ ۳ — «تمام cast» (نیازمند artwork مالک)

Dana (همراه مسیر) و Roka (چالش آخر مرحله). **هیچ‌کدام pose shipped ندارند** تا تصویرسازی خلق نشود:
درخواست رسمی به مالک با این فهرست دقیق:

1. `Dana_01_front` (مقصد: cameo مسیر — جایگزین مهم نیست، تکملی است)
2. `Roka_15_determined` (مقصد: صفحهٔ چالش — playbook 13)
3. `Fandogh_11_cheer` (مقصد: empty/راهنمای تمرین — ارتقای pose 01 موجود)

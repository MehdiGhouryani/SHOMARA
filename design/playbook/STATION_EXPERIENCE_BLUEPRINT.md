## ۲. معماری هدف — StationHost V3

```
┌────────────────────────────────────────────┐
│ StationTopBar        (48dp, ثابت)          │  ← ×/توقف (آیکون، نه دکمهٔ متن) · stage-chips · صدا
├────────────────────────────────────────────┤
│ SceneCanvas           (weight=1)           │  ← رندر الگوی فعال؛ مانیپولاتیو hero؛ بدون اسکرول
│  · TemplateRenderer(params, state, onX)    │
│  · راهنما/شخصیت فقط وقتی مجاز (charter)    │
├────────────────────────────────────────────┤
│ BottomCtaSlot         (pinned, ثابت)       │  ← تنها یک CTA اصلی؛ ثبت/ادامه/بعدی
├────────────────────────────────────────────┤
│ FeedbackSlot          (pinned بالای CTA)   │  ← بنر بازخورد/بازیابی — هرگز اسکرول نمی‌شود
╞════════════════════════════════════════════╡
│ OverlayLayer (فقط هنگام رویداد)            │  ← ExitSheet · StageIntro · Celebration · Pause
└────────────────────────────────────────────┘
```

**قواعد ناگسستنی (invariants):**

1. **UI هرگز داوری نمی‌کند** — پیشروی مرحله/آیتم فقط از ارزیاب محلی نسخه‌دار (ADR-0039).
   StationHost فقط رندر و رویداد است.
2. **در هر حالت فقط یک CTA اصلی** — خروج/توقف هرگز CTA اصلی نیست؛ آیکون ۴۸dp گوشهٔ بالا-شروع (RTL).
3. **SceneCanvas اسکرول نمی‌شود** — محتوای الگو در صحنه جا می‌شود (چیدمان seed + مقیاس واحد ≥۳۲dp)؛
   اسکرول فقط در دیالوگ‌های والد/متن.
4. **هر حرکت «اطلاعاتی» است یا حذف می‌شود** — بخش ۴.
5. **رشته فقط از `strings.xml`** — هیچ literal فارسی در Kotlin (نقض‌های فعلی در S0 پاک می‌شوند).
6. **هدف لمسی:** مانیپولاتیو ۷۲–۸۰dp؛ دکمه‌های خروج/صدا ۴۸dp؛ فاصلهٔ لمس‌ها ≥۲۴dp.

### ۲.۱ بازطراحی خروج/توقف (جایگزین A1+A2)

- **آیکون «خانه/×» گوشهٔ بالا-شروع** → باز کردن `StationExitSheet` (bottom-sheet با scrim ۴۰٪).
- Sheet: عنوان «بازی را رها می‌کنی؟» · متن «جای‌ات همین‌جا ذخیره می‌شود» ·
  **CTA primary بزرگ: «ادامه می‌دهم»** (برگشت به بازی) · دکمهٔ ثانویه متن‌ساده: «خروج به نقشه».
- **بک‌سیستم/بک-ژست همان Sheet را باز می‌کند** (منطق `ShomaraCloseConfirmLogic` حفظ می‌شود؛
  فقط رندر از بنر→شیت منتقل می‌شود؛ state machine و تست‌های موجود دست‌نخورده).
- بستن Sheet با لمس scrim = «می‌مانم». هیچ مسیری بدون تأیید ذخیره checkpoint خارج نمی‌شود.
- در S13 ارزیابی، Sheet هشدار اضافه دارد: «این آزمون کوتاه است؛ با خروج از اول شروع می‌شود.»

### ۲.۲ Direction/مرحله (جایگزین A7)

`StageChips`: پنج خانهٔ کوچک (پیداکن/تمرین/بازی/خودت/چالش) با حالت‌های
`done · current · locked` — بدون عدد و بدون درصد؛ مرحلهٔ جاری با پرشدگیِ نرم token-دار.
اعلام TalkBack: «مرحلهٔ دوم از پنج: تمرین با راهنما».

## ۴. سیستم حرکت — لایهٔ روایی (Narrative Motion)

قرارداد فعلی «هیچ AnimatedVisibility» را با دقت اصلاح می‌کنیم: **حرکتِ روایی =
اطلاعات است، نه تزئین.** همان‌قدر که رنگ حالت را نشان می‌دهد، «چه چیزی عوض شد و کجا» را
نشان می‌دهد. همهٔ حرکت‌های روایی: token-دار، تک‌مالک، کوتاه (≤۴۰۰ms) و با fallback کاهش‌حرکت.

### ۴.۱ لحظه‌ها (Motion Moments)

| لحظه | چه چیزی می‌گوید | مشخصه | کاهش‌حرکت |
|---|---|---|---|
| `stageEnter` | «به مرحلهٔ تازه رسیدی» | اسلاید+فید ۱۲۰→۲۴۰ms، از جهت RTL شروع | cut + StateSurface ثابت |
| `stageExit` | «این مرحله تمام شد» | فید-خارج ۱۲۰ms + مقیاس ۰٫۹۸ | cut |
| `itemOk` | «درست بود» | پاپ مقیاس ۱→۱٫۰۴→۱ (spring موجود) + tick رنگی ۲۴۰ms | تغییر رنگ/آیکون فقط |
| `itemRetry` | «دوباره» | لرزش افقی ±۶dp، ۲ بار، ۲۴۰ms؛ **هرگز قرمز تند/صدا تند** | هایلایت ثابت ملایم |
| `reveal` (کشف P1) | «نمایش تازه» | ظهور عنصر با فید+رشد ۲۴۰ms، ترتیب دارد | ظهور فوری، ترتیب حفظ |
| `countPulse` (T01/T02) | «این شمرده شد» | حلقهٔ ۴۰۰ms روی شیء + حباب عدد | حلقهٔ ثابت ۶۰۰ms |
| `snapIn` (T04/T08) | «جای درست» | snap فنری + فلاش لبه ۱۲۰ms | تغییر حالت فوری |
| `fold` (T07) | «دو نیمه یکی‌اند» | انیمیشن تا ۴۰۰ms | محو متقاطع (قرارداد T07) |
| `sheetUp` (ExitSheet/…) | «روی بازی، نه در بازی» | اسلاید-بالا ۲۴۰ms + scrim فید | ظهور فوری + scrim ۱۰۰٪ |
| `celebration` | «ایستگاه کامل شد» | تک‌مالک (gate)؛ شخصیت + ذرات ≤۱۵۰۰ms، یک‌بار | کارت نتیجهٔ ثابت |

قواعد: هر لحظه فقط از توکن‌های `ShomaraTokens.Motion*` می‌خواند (بدون ms خام در کد)؛
دو لحظهٔ هم‌زمان روی یک سطح ممنوع (گیت celebration الگو را تعمیم می‌دهد)؛ هر لحظه
باید تست واحدِ منطق + تست `reducedMotion=true` داشته باشد.

### ۴.۲ RTL و جهت

ورود مرحله از «راست» (شروع خواندن)؛ `stageEnter` جهت را از `LayoutDirection` می‌گیرد نه
هاردکد؛ ذرات جشن تقارن عمودی دارند تا در RTL/LTR یکسان حس شوند.

## ۵. قرارداد کامپوننت الگوها (Template Component Contract)

هر الگوی T01–T15 یک Composable مستقل در `core:designsystem:lesson-templates` با این امضاست:

```kotlin
@Composable
fun TemplateT01(
    params: T01Params,            // typed — از projection محتوا (stage5 §7)
    state: TemplateState,         // Idle | Active(sel/count…) | Feedback(ok/retry) | Hint(level)
    callbacks: TemplateCallbacks, // onObjectTap / onAnswer / onReplayAudio / onHint
    motion: ShomaraMotionScope,   // لحظه‌های §۴ با reducedMotion حل‌شده
)
```

- **states اجباری هر الگو:** idle · active · درست · دوباره · هر سه سرنخ (h1/h2/h3 مطابق stage5).
- **پذیرش الگو = پذیرش stage5 همان الگو** (مثلاً T01: لمس دوباره عدد تازه نمی‌سازد؛ ۲۵۰ms فاصله).
- کارت‌های پاسخ (T15): جای گزینهٔ درست تصادفی در هر render seed-دار؛ گزینهٔ غلط از جدول خطای رایج.
- **placeholder تصویر تخت** تا فاز دارایی (تصمیم مالک): هر OBJ.* فعلاً shape/دایرهٔ token-دار؛
  محتوا قطعی است و گرافیک بعداً بدون تغییر قرارداد جایگزین می‌شود.

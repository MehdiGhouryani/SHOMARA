# مرحلهٔ ۶: قالب مشخصات ایستگاه و بازی

**وضعیت:** قالب نهایی پیشنهادی. نمونهٔ کامل آن ایستگاه ST07 است (`shomara-stage7-pilot-ST07.md`). برای هر ۲۵ ایستگاه یک فایل مشخصات با همین ساختار نوشته می‌شود.
**مخاطب:** برنامه‌نویس یا مدل هوش مصنوعی که باید بدون پرسش اضافه ایستگاه را پیاده کند، و مسئول محتوا که باید ایستگاه را بنویسد و بازبینی کند.
**ورودی‌های مرجع:** مرجع‌های مشترک (`shomara-stage5-shared-references.md`)، معماری (`shomara-stage4-architecture.md`) و مطالعهٔ کتاب‌ها (`shomara-stage1-study.md`).

---

## ۱. اجزای هر ایستگاه

هر ایستگاه سه خروجی دارد:
1. **فایل مشخصات (md):** متن توضیحی و بلوک‌های YAML برای ماشین.
2. **فهرست صدا (CSV):** همهٔ خط‌های صوتی ایستگاه برای وارد کردن در پنل ادمین.
3. **گزارش اعتبارسنجی:** خروجی خودکار که در انتهای فایل مشخصات می‌آید.

خط‌های عمومی (`G.*`)، عددها (`N.*`)، ترتیبی‌ها (`O.*`) و واژه‌ها (`W.*`) فقط یک بار در فایل جهانی `shomara-global-audio-manifest.csv` هستند و در فایل ایستگاه تکرار نمی‌شوند.

## ۳. طرح داده‌ها (YAML)

### ۳.۱ شناسنامه
```yaml
station: ST07
name: عددهای ۱ و ۲
chapter: {number: 2, current_name: …}
book: {unit: 7, plate_pdf: 49, work_pages_pdf: "50 تا 55"}
prerequisites: [ST01, …]
skills: [{id: SK-ST07-1, text: …}, …]
templates: [T01, T05, T13, T15]
estimated_minutes: {P1: 1.5, P2: 3, P3: 3, P4: 1.5, P5: 1.5}
audio_policy: {display_numerals_allowed: [1, 2]}
version: 1
status: draft            # draft | validated | reviewed | approved
```

### ۳.۲ قدم بخش ۱
```yaml
- id: ST07.P1.s01
  kind: discover            # intro | discover | transition
  template: T01
  params: {mode: discover, cards: [OBJ.sun, …], card_labels: [ST07.P1.s01.a, …], reveal: GLYPH.1}
  guide: {pose: CH.guide.think, size: small}
  audio: {pr: ST07.P1.s01.pr, done: ST07.P1.s01.done}
  interaction: «شرح کوتاه رفتار»
  advance: «چه وقت جلو می‌رود»
  idle_replay_s: 8
  assets: […]
```

### ۳.۳ آیتم (بخش‌های ۲ و ۴ و ۵)
```yaml
- id: ST07.P2.i01
  template: T15            # یکی از T01 تا T15
  level: 1
  skill: [SK-ST07-3]       # در بخش ۵ می‌تواند مهارت ایستگاه قبل باشد (مرور مارپیچی)
  params: {…}              # پارامترهای مخصوص همان الگو (مرجع مشترک، بخش ۷)
  audio:
    pr: ST07.F2.pr.top     # دستور
    h1: ST07.S.pick.h1     # سرنخ‌ها
    h2: …
    h3: …
    ok: ST07.P2.i01.ok     # تأیید ویژهٔ آیتم (اختیاری)
    ok_generic: G.ok.*     # دستهٔ عمومی تأیید
    retry: G.retry.*
  answer: {type: option, value: 1}
  assets: [OBJ.ball, UI.card.numeral]
  notes: …                 # اختیاری
```
- بخش‌های ۴ و ۵ سرنخ ندارند؛ فقط `pr` و `ok_generic`/`retry` (تأیید خنثی).
- آیتم مرور باید `notes` داشته باشد که مهارت و ایستگاه مبدأ را بگوید.

### ۳.۴ بازی (بخش ۳)
```yaml
game: {id: ST07.P3, template: T05, theme: …, intro_audio: ST07.S.cake, rounds: 6,
       retry_allowed: true, hints: [h1, h2], end: G.win.*}
rounds: [ …آیتم‌ها مانند ۳.۳… ]
```

### ۳.۵ خانوادهٔ استخر (بخش ۴)
```yaml
draw_rule: {count: 4, one_from_each_family: [F1, F2, F3, F4], exclude_seen_in_last_attempt: true,
            recheck: …, pass_threshold: «۳ از ۴», skills_map: {F1: SK-…}}
families: [{id: F1, template: T13, desc: …, size: 4}, …]
```
- حداقل ۱۲ آیتم در استخر لازم است (مرحلهٔ ۴)؛ کمینهٔ پیشنهادی ۲۰ تا ۲۶ برای تمرین.
- آیتم‌های استخر شناسهٔ یکتا و پارامتر کامل دارند.

### ۳.۶ خط صوتی (جدول و CSV)
```
id, kind, text_display, text_tts, voice, rate, status, used_by, notes
```
- `kind`: `pr` دستور، `hint` سرنخ، `ok` تأیید ویژه، `ex` توضیح، `label` برچسب شیء، `nr` روایت مسئله.
- `text_display` ممکن است خالی باشد (وقتی تصویر کافی است یا عدد آموزش‌داده‌نشده نباید دیده شود).
- `voice`: `fa-IR-DilaraNeural` یا `fa-IR-FaridNeural`؛ `rate`: مقدار اولیه `-15%`؛ `status` اولیه `draft`.

### ۳.۷ دارایی
```
id: OBJ.sun | GLYPH.1 | UI.tray | PAT.up | CH.guide.idle
type: illustration | glyph | ui | pattern | character
desc: «توضیح برای تصویرگر»
```
پیشوندها: `OBJ` شیء، `GLYPH` نماد، `UI` رابط، `PAT` عنصر الگو، `CH` شخصیت.

## ۴. چک‌لیست نویسنده

1. هر صفحهٔ کتاب در جدول قلمرو جایی دارد یا صراحتاً «خارج از ایستگاه با دلیل» است.
2. هر مهارت دست‌کم یک آیتم در بخش ۴ دارد (تسلط قابل ارزیابی).
3. بخش ۴ یک آیتم از هر خانواده می‌گیرد؛ استخر ≥ ۱۲.
4. هر آیتم یک الگو (T01 تا T15)، سطح و پاسخ دارد.
5. هیچ متن گفتاری رقم یا حرف لاتین ندارد؛ عددها با حروف.
6. هیچ متنی «غلط» یا «اشتباه» نمی‌گوید.
7. متن نمایشی ≤ ۱۰ واژه و فقط عددهایی دارد که تا آن ایستگاه آموزش داده شده‌اند.
8. محتوای دینی یا عکس واقعی کتاب بدون تصمیم شما وارد نشود؛ جایگزین خنثی و یادداشت.
9. حداقل یک آیتم مرور از ایستگاه‌های قبل در بخش ۵.
10. همهٔ شناسه‌ها یکتا و مطابق الگوی ۱٫۳ مرجع مشترک.

## ۵. قواعد اعتبارسنجی خودکار

| قاعده | شدت |
|---|---|
| رقم یا حرف لاتین در متن گفتار | خطا |
| واژهٔ ممنوع («غلط»، «اشتباه») در صدا یا متن نمایشی | خطا |
| متن گفتار بیش از ۱۰ واژه (روایت مسئله بیش از ۱۴) | خطا |
| متن نمایشی بیش از ۱۰ واژه | خطا |
| عدد نمایشی بزرگ‌تر از عددهای آموزش‌داده‌شدهٔ ایستگاه | خطا |
| شناسهٔ تکراری (خط، دارایی، آیتم) | خطا |
| الگوی بازی خارج از T01 تا T15 | خطا |
| ارجاع به خط صوتی یا دارایی که وجود ندارد | خطا |
| عنصر هنری ممنوع (ستاره، تاج، سکه، جام، قلب، آتش) در توضیح دارایی | خطا |
| خط صوتی بدون ارجاع | هشدار |
| استخر کمتر از ۱۲ آیتم | خطا |

## ۶. جریان کار

`پیش‌نویس ← اعتبارسنجی‌شده ← بازبینی انسانی ← تأییدشده`
- نویسنده فایل را می‌سازد و اعتبارسنج را اجرا می‌کند؛ بدون «خطا» به بازبینی می‌رود.
- بازبین انسانی (شما) فقط محتوای آموزشی، تلفظ و جایگزینی‌های حساس را می‌بیند.
- پس از تأیید، CSV صوتی به پنل ادمین داده می‌شود و ادمین TTS می‌سازد و می‌شنود.

## ۷. آنچه این قالب تعیین نمی‌کند

- طراحی نهایی تصویرها و انیمیشن‌ها (فقط توضیح و محدودیت).
- معماری کد و سرور (فقط رفتار و داده).
- مقدارهای نهایی صدا، زمان و تلرانس (مقدار اولیه‌اند؛ آزمون دستگاه و کودک لازم است).
